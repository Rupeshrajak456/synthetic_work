Steps 4 and 5

Asking a machine to copy, not to interpret

The prompt asks a language model for exact phrases sorted into the researcher's categories, and nothing else. Every phrase it returned was then checked against the text before it was allowed to count.

Step 4

The extraction prompt

Model prompt followed
prompt.txt from the Wife's Letter project.

Files
prompt.txt
full_prompt.txt (with the story inserted)

The prompt carries the research question and claim, so that the model knows what the phrases are for, but it gives the model no room to argue. Its design choices are deliberate.

  • Exact copying. Phrases must appear in the passage word for word. A paraphrase cannot be checked; a copy can.
  • Shortest meaningful phrase. Keeps matches precise and stops a single long sentence from standing in for several ideas.
  • One sub-type per phrase. Forces a decision, so that counts per category do not overlap.
  • Empty lists allowed. The model is told not to force evidence into a category, which reduces invented matches.
  • Narration and dialogue. The model is warned not to confuse them. Much of this story is told inside quotation marks by Brodribb and Thorndyke, so the distinction is measured afterwards on the Analysis page.
  • JSON only. A fixed structure that a script can read without cleaning.

The brief preferred a specialised local model. A hosted chat model was used instead, and that has consequences worth stating. A hosted model can change between versions, so the same prompt may not return the same list next year. To make the result checkable anyway, the exact prompt and the untouched answer are both stored in the repository, and every downstream number is computed from the stored answer, not from a new run. The model's role was limited to proposing phrases; whether they count was decided by string verification and by the researcher.
